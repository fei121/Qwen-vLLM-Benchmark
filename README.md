# Qwen3.6-35B-A3B-FP8 × RTX PRO 6000

## 一张卡，还是两张卡？

这是一次面向真实服务决策的 vLLM 推理实验：在完全相同的 300 个请求、20 路并发、4K 输入 / 1K 输出负载下，对比 RTX PRO 6000 单卡与双卡运行 `qwen3.6-35b-a3b-fp8` 的表现。

![吞吐与完成时间对比](assets/throughput.svg)

## 先说结论

第二张卡没有带来线性加速，却实实在在改变了服务体验：

- 输出吞吐从 **1,451.64 tok/s** 提升到 **2,009.36 tok/s**，增加 **38.4%**；
- 测试完成时间从 **211.62 s** 降到 **152.88 s**，缩短 **27.8%**；
- 平均 TTFT 降低 **56.7%**，P99 TTFT 从 **6.28 s** 降到 **1.85 s**；
- 双卡并行效率约 **69.2%**，每百万输出 token 的 GPU 时间反而增加约 **44.5%**。

如果你在意交互式服务的首 token 延迟和尾部体验，双卡值得；如果你在意单位 GPU 成本和单卡产出，单卡仍然是更高效的选择。

这不是“翻倍加速”的故事，而是一次典型的容量与成本之间的取舍。

## 这组数据最值得看的地方

平均值只讲了一半故事。

单卡的平均 TTFT 是 535 ms，中位数只有 180 ms，但 P99 达到 6.28 s。大多数请求来得很快，少数请求却会等很久。双卡把 P99 压到 1.85 s，减少了 4.43 s 的长尾；这往往比平均吞吐增加 38% 更能影响用户对系统“快不快”的感受。

解码阶段也得到了相对稳定的改善：平均 TPOT 从 13.02 ms 降至 9.52 ms，P99 从 27.82 ms 降至 20.32 ms。只是 ITL 的 P99 仍有 115.87 ms，说明偶发抖动并没有被第二张卡完全消除。

## 一张卡和两张卡，分别适合什么？

**单卡**更适合对单位资源产出敏感的场景：容量已经够用，或者可以通过降低并发来换取更稳定的尾延迟。

**双卡**更适合有明确 P99 SLO、需要更高服务容量，或希望在固定时间内完成更多请求的场景。它购买的主要不是“2 倍速度”，而是更大的吞吐余量和更短的等待长尾。

## 关于这次实验

这是一组单次本地运行结果。当前记录没有包含 vLLM 版本、双卡并行策略、完整启动参数、GPU 功耗与频率、请求随机种子以及重复试验方差。因此，本文把结论限定为两次运行之间的观测差异，不把所有变化简单归因于 GPU 数量。

如果要把它升级成容量规划基线，下一步应补充并发扫描、重复试验、投机解码 on/off 对照、不同输入输出长度，以及 GPU 利用率和跨卡通信数据。
